The one fact that drives the design: CodeView is the supported API for a multi-file diff review surface — it already does intra-file (line-range) virtualization, anti-blanking, scroll anchoring, element pooling, and selection — and we already have it installed. Our custom layer reimplements a worse subset of it, and only windows between files (a single 5k-line file mounts every row today).

Why this is worth doing — the 3 problems that actually bite

① File-level windowing only

Once a file enters the window its whole <FileDiff> mounts. A 5k-line file = 5k DOM rows. CodeView renders only visible lines via binary search.

② Two divergent copies

DiffEditor & HunkReview each re-implement window-building, scroll-anchor capture/restore, and a load queue. Bugs fixed in one drift from the other.

③ Hand-maintained guesses

estimateDiffFileHeight multiplies magic constants then patches with measured heights. Wrong estimates cascade into scroll jumps. CodeView measures deltas internally.

The target shape (rudu, verified)

// items: one controlled record per file — CodeView virtualizes the lines inside
const items = useMemo<CodeViewItem<Ann>[]>(() =>
  files.map((file) => ({
    id: getCodeViewItemId(file.fileDiff.name),
    type: "diff",
    fileDiff: file.fileDiff,            // FileDiffMetadata from parsePatchFiles (worker)
    annotations: buildLineAnnotations(file), // comments + draft + hunk accept/reject
    collapsed: collapsedPaths.has(file.path), // native collapse
    version: buildCodeViewVersion(file),     // hash → re-render just this item
  })), [files, collapsedPaths]);

<CodeView
  ref={codeViewRef}                  // addItems · scrollTo · setSelectedLines
  items={items}                       // controlled mode
  options={options}                   // theme · diffStyle · itemMetrics · stickyHeaders
  selectedLines={selectedLines}       // controlled → comment composer
  onSelectedLinesChange={…}
  renderAnnotation={renderAnnotation} // comment threads + accept/reject buttons
  renderHeaderMetadata={renderHeaderMetadata} // our per-file badges
/>
